# AiToEarn Codex 插件安装指令

请帮我安装本目录中的 AiToEarn Codex 插件。技能与 MCP 连接必须都完成，不能只安装技能或只写入配置文件就宣称成功。所有检查、注册和文件操作由你完成，不要把注册命令交给用户手工执行。

1. 先确认目标版本：中国版使用 `aitoearn-cn` 与 `https://aitoearn.cn/api/ai/agent/mcp`；国际版使用 `aitoearn` 与 `https://aitoearn.ai/api/ai/agent/mcp`。两个版本只保留一个。
2. 确认插件包目录，读取包内 `.mcp.json`、插件清单和当前 `codex mcp add --help`。不要从包外寻找或复制旧凭证。
3. 按 Codex 的本地 marketplace 流程安装并启用 `aitoearn` 插件。更新插件时不得默认删除现有 MCP；只有用户明确要求清理重装、切换版本，或确认修正错误配置时，才删除对应 AiToEarn 条目，且不得影响其他 MCP 服务。
4. **自动检查并注册 MCP**：先运行 `codex mcp get <name> --json`。
   - 已存在且 server 名、传输方式及 URL（或 stdio 启动配置）正确：直接复用，不删除、不重复注册、不主动重新授权。
   - 不存在：由你自动执行 `codex mcp add`。
   - 同名但配置不符：展示差异并取得用户确认后再修正，不得静默覆盖。
5. **不限制 MCP 连接类型**：以包内声明和当前 Codex CLI 官方帮助为准。URL 服务使用 `codex mcp add <name> --url <URL>`；stdio 服务使用 `codex mcp add <name> -- <COMMAND> [ARGS...]`，需要时再使用 CLI 支持的 `--env`。不得擅自转换传输方式；当前 Codex 不支持的类型要如实报告，不得编造参数。AiToEarn 官方服务当前是 URL 服务，缺失时执行对应命令：
   - 中国版：`codex mcp add aitoearn-cn --url https://aitoearn.cn/api/ai/agent/mcp`
   - 国际版：`codex mcp add aitoearn --url https://aitoearn.ai/api/ai/agent/mcp`
6. 注册后再次运行 `codex mcp get <name> --json` 和 `codex mcp list`，确认目标 server 实际出现且为 `enabled`。仅看到 `.mcp.json`、插件清单或设置页声明不算注册验证通过。
7. **自动发起 OAuth，用户只负责主动确认授权**：
   - 中国版需要授权时运行 `codex mcp login aitoearn-cn --oauth-client-registration dcr`，`dcr` 必须保留；默认 CIMD 依赖服务端访问 chatgpt.com，中国版部署环境不可达。
   - 国际版需要授权时运行 `codex mcp login aitoearn`，使用默认方式，无需 DCR。
   - 如果 `codex mcp add` 已自动进入 OAuth 流程，直接引导用户完成，不重复执行 `login`。
   - 已有有效授权不要重复登录；不要仅因更新、重装或重启而重新授权。只有服务明确返回未授权、授权过期，或用户主动要求切换账号时才重新授权。
   - 桌面版可在 设置 → 插件 → MCP 中授权；中国版选择「动态客户端注册 (DCR)」，国际版使用默认方式。不得要求用户手工选择 MCP 传输类型或填写启动命令。
8. 完全退出并重启 Codex，在新会话中发送「列出可用的发布渠道」验证。只有 AiToEarn 工具实际出现并返回渠道列表，才能报告安装与连接均完成。
9. 分别报告插件安装、MCP 注册、OAuth 授权和渠道验证状态。若没有 OAuth 入口、授权失败或工具未出现，明确说明尚未完成的环节并保留错误信息；`enabled` 只表示配置启用，不表示已授权或连接成功。绝不改用旧静态请求头、环境变量或 API Key。

用户不懂编程：所有文件操作和命令由你完成。遇到权限拦截，先使用当前应用的授权机制；没有权限就说明无法完成安装，并建议使用该平台的官方安装方式。
