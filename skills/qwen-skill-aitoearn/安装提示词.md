# AiToEarn 千问技能 安装指令

请帮我安装 AiToEarn（千问技能）。按下面步骤执行：

## 如何定位插件包

- 如果你是通过文件路径读取到这份文档的：插件包目录就是本文件所在的目录，直接使用它，不要去找其他路径。
- 如果你是在对话框里看到这段文字的：插件包默认位于本仓库 `skills/qwen-skill-aitoearn` 目录（如果 skills 文件夹被移动或单独下载过，以实际路径为准）；如果该目录不存在，先向我询问实际路径再继续，不要使用其他来源的文件。

## 开始前检查

开始执行前先确认你能读写我的用户主目录（安装会写入 ~/.codex、~/.qwenworkcn、~/.dsh、~/.trae-cn、Library/Application Support 等位置，按本平台的步骤需要哪些就确认哪些）。如果确认没有权限，现在就告诉我，不要做到一半才失败。

第 0 步：请提供你的 AiToEarn API Key（获取方式：登录 aitoearn.cn → 设置 → API Key → 创建；如果给的是国际站 aitoearn.ai 的 Key 也请说明）。

## 安装步骤

技能（SKILL.md）与 MCP 连接两部分都必须完成，缺一不可；只完成一半不算安装完成。

1. 找到千问技能库：`~/Library/Application Support/Qianwen/qwen-agent/*/skills`（先确认我登录过千问桌面端；找不到就提醒我打开一次千问再重试）。
2. 把插件包目录下的 `aitoearn` 子目录复制到该 skills 目录下。
3. 编辑 skills 目录下的 `.cloud-skills.json`：把插件包里的 `cloud-skills-entry.json` 中 `skills.local_aitoearn_0001` 合并进去，`localPath` 改为刚复制到的完整路径，时间戳改为当前 UTC 时间，`recordRevisionCounter` 加 1。若文件不存在，先用 `{"recordRevisionCounter": 1, "generatedAt": "<now>", "skills": {} }` 为骨架再合并。
4. 提醒我在千问「连接」里手动添加连接器：名称 AiToEarn、类型 HTTP、URL `https://aitoearn.cn/api/ai/agent/mcp`（国际站 Key 用 `https://aitoearn.ai/api/ai/agent/mcp`）、Header `X-Api-Key` = 我在第 0 步提供的 Key。
5. 验证时必须新建任务（旧任务不会加载新连接器）。

## 安装完成后

提醒我必须完全退出并重新打开千问桌面端（不是关闭窗口），重启后新会话才会加载插件、技能与 MCP 连接。

## 验证（这一步同时检验 MCP 是否配好）

重启客户端后，在新会话里发送「使用全域内容运营助手技能，列出可用的发布渠道」：

- 能正常返回渠道列表 → 技能与 MCP 都安装成功；
- 如果提示没有相关工具、找不到渠道或连接失败 → 说明 MCP 没配好，必须明确告诉我“MCP 还没配置”，然后按下面「MCP 手动兜底」处理，配好后让我再次验证；绝对不允许只装技能就告诉我安装完成。

## MCP 手动兜底（自动配置失败时）

回到「安装步骤」第 5 步核对连接器：
1. 名称是否为 AiToEarn、类型 HTTP、地址 `https://aitoearn.cn/api/ai/agent/mcp`（国际站 `https://aitoearn.ai/api/ai/agent/mcp`）；
2. Header `X-Api-Key` 是否是我在第 0 步提供的 Key；
3. 修正后**新建任务**重试（旧任务不会加载新连接器）。

## 失败处理

- 任何一步失败，立即停止后续操作，用我能看懂的大白话告诉我卡在哪一步、缺什么，不要假装成功。
- 我不懂编程，也几乎不会用终端：**绝对不要给我终端命令、脚本或代码让我自己执行**。所有文件操作必须由你通过你自己的工具完成。
- 遇到系统权限拦截（例如 Operation not permitted / 权限被拒绝）时：先通过你所在应用自带的授权机制向我申请对应目录的访问权限，并提醒我在弹出的授权窗口里点「允许」；如果该应用没有授权机制、确实访问不了那些目录，直接明确告诉我“当前应用无法完成安装”，告诉我应该换用什么方式（例如改用官方安装器或该平台内置的插件市场），然后停止。
- 需要我在客户端里手动点击的步骤，给我一步一步的点击指引：点哪个菜单、选哪一项、填什么。
